### 3. Assessment: lowest-common-denominator seam

**(a) Identity.** The only thing all four give an MCP server for free is *its own parent process*: `getppid()` + `ps -o command= -p $PPID` distinguishes `claude` / `codex` / `gemini` (node) / `cursor-agent` (node) — and `cwd` at spawn. Vendor session ids reach the server natively only on Claude (`CLAUDE_CODE_SESSION_ID`, verified). Gemini passes none (verified in code); Codex and Cursor UNVERIFIED. So the LCD is: server identity = `(vendor from parent exe, ppid, cwd, server-generated id)`, with the **agent calling an explicit `register(name)` tool** to attach a human-readable handle. Every CLI has a hook that *does* carry the session id (`SessionStart`: Claude `session_id`, Codex `session_id`, Gemini `session_id`/`GEMINI_SESSION_ID`, Cursor `conversation_id`), so a hook can drop a `<ppid or pid>.json` breadcrumb the server correlates by parent pid — but that's a second moving part, and Codex hooks need per-definition trust.

**(b) Presence.** LCD = MCP server process lifetime, hardened with a `ppid`-liveness watchdog (when the parent dies the server is reparented to launchd; exit and mark offline) and a heartbeat file readers cross-check against `kill -0 pid`. Do not trust file existence alone — Claude leaves stale `/tmp/cc-socks/*.sock` for dead pids. Gemini closes connections to servers that register **no tools**, so a presence-only server must still expose at least one tool. Native extras only on Claude (`claude agents --json`, `$CLAUDE_CONFIG_DIR/sessions/<pid>.json`, per config dir) and Codex (daemon `thread/list`, only when sessions run through the daemon).

**(c) Pull delivery.** An MCP `inbox` tool works identically on all four and is the only channel that is never auto-injected. Per-tool deny for unattended runs exists on all four (`--disallowedTools`/`permissions.deny` `mcp__dm__*`; Codex `disabled_tools`/`-c`; Gemini `excludeTools`/policy deny; Cursor `Mcp(dm:*)`). A metadata-only nudge ("N unread") is possible via prompt hooks on Claude (`UserPromptSubmit`), Codex (`UserPromptSubmit` stdout), Gemini (`BeforeAgent` additionalContext); Cursor only at `sessionStart`/`postToolUse`. Push exists but is vendor-locked and auto-injecting: Claude `SendMessage`, Codex `queue`, Cursor `followup_message`. None is cross-vendor.

### 4. Risks

- **Claude auto-injects**: peer messages land in the transcript between tool calls or start a new turn; default is deliver for prompting-mode receivers; `-p` sessions bind an inbox too; the socket accepts raw JSON from any same-user process, and a token-holding child is delivered even in bypass mode. Under `refuse` the socket still binds; `--settings` values aren't validated on the flag channel (darker's own probes). Only `--bare` doesn't bind.
- **Codex `queue` is a user turn**: anything that can reach the daemon socket or `queue_1.sqlite` can inject the next prompt; only when the session is daemon-attached (embedded-server sessions UNVERIFIED).
- **Cursor `stop` hook `followup_message` auto-submits**, hooks fail-open by default.
- **Hook stdout is context** on Claude/Codex (`SessionStart`, `UserPromptSubmit`) and Gemini (`SessionStart`, `BeforeAgent`) — a DM hook must never emit message bodies there.
- **MCP lifetime ≠ session**: Claude docs literally say MCP subprocesses "outlive the session that spawned them" (ID-changes-on-`/clear` sense; no reparented orphans found today, kill-at-exit UNVERIFIED); Claude does not reconnect a dropped stdio server; Codex daemon-hosted sessions share one environment; Gemini drops tool-less servers.
- **Credential scrubbing**: Claude strips env names containing `TOKEN/SECRET/PASSWORD/KEY/AUTH` for project `.mcp.json`/plugin servers (user-scope servers got `CLAUDE_CODE_MESSAGING_TOKEN` live; project-scope UNVERIFIED); Gemini redacts the same patterns unless set in `env`.
- **Enumeration scope**: `claude agents --json` is per `CLAUDE_CONFIG_DIR`; a nested `claude` (`CLAUDE_CODE_CHILD_SESSION=1`) is excluded unless `CLAUDE_CODE_FORCE_SESSION_PERSISTENCE=1`.
